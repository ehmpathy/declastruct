## defect 1: jest cannot find .js imports

**what**: integration test failed with `Cannot find module './getRefByPrimary.js'`

**how** (diff against origin/main):
```diff
# tsconfig.json
- "module": "commonjs",
- "moduleResolution": "node",
+ "module": "node16",
+ "moduleResolution": "node16",
```

**why**: node16 module resolution requires .js extension in imports for ESM compatibility. the source files use `import { getRefByPrimary } from './getRefByPrimary.js'` but jest/swc tries to find a literal `.js` file. typescript compiles `.ts` to `.js`, but in test mode we run directly against source `.ts` files.

**fix**: added moduleNameMapper to all three jest configs:
```typescript
moduleNameMapper: {
  // node16 module resolution uses .js in imports; map to .ts for jest
  '^(\\.{1,2}/.*)\\.js$': '$1',
},
```

files modified:
- `jest.unit.config.ts`
- `jest.integration.config.ts`
- `jest.acceptance.config.ts`

## defect 2: circular dependency lint failure (transitive deps)

**what**: `npm run test:lint:cycles` failed detecting cycles in domain-objects@0.31.9 and helpful-errors@1.5.3

**how** (diff against origin/main):
```diff
# package.json - new devDependency
+ "dpdm": "3.14.0",

# package.json - new npm command
+ "test:lint:cycles": "dpdm --no-warning --no-tree --transform --exit-code circular:1 src",
```

**why**: `test:lint:cycles` is a NEW check from declapract practices upgrade. transitive dependencies (via dao-helper-daos and type-fns) pulled in old versions with circular imports. the cycles always existed but were never detected before.

**fix**: added pnpm overrides to force latest versions:
```json
"pnpm": {
  "overrides": {
    "domain-objects": "0.31.13",
    "helpful-errors": "1.7.3"
  }
}
```

## defect 3: circular dependency lint failure (bottleneck)

**what**: `npm run test:lint:cycles` detected cycle in bottleneck@2.19.5 (Bottleneck.js ↔ Group.js)

**how**: same new lint check as defect 2

**why**: bottleneck 2.19.5 is the latest version (unchanged since 2020). the internal cycle (Bottleneck.js ↔ Group.js) is by design in the package architecture, not a code quality issue.

**fix**: added exclusion to .dpdmrc.yaml with documentation:
```yaml
exclude:
  # bottleneck 2.19.5 (latest, unchanged since 2020)
  # internal cycle: Bottleneck.js <-> Group.js
  # dpdm detects what already exists in the package
  # this is by design, not our code
  - bottleneck
```
