# 2.detect.hazards — iteration 1

## summary

4 potential hazards detected from declapract upgrade changes.

---

## hazard 1: tsconfig module resolution change

**what changed**:
```diff
- "module": "commonjs",
- "moduleResolution": "node",
+ "module": "node16",
+ "moduleResolution": "node16",
```

**why it may break**:
- node16 module resolution requires explicit file extensions in imports
- extant imports without extensions may fail type check
- could affect how jest resolves modules

**how to verify**:
```sh
rhx git.repo.test --what types
```

---

## hazard 2: file path renames

**what changed**:
- `provision/github/declastruct.resources.ts` → `provision/github.repo/resources.ts`
- `src/domain/constants.ts` → `src/domain.objects/constants.ts`

**why it may break**:
- any imports that reference old paths will fail
- CI workflows may reference old paths

**how to verify**:
- grepped for old paths — no references found
- low risk

---

## hazard 3: new lint cycle check

**what changed**:
- added `dpdm` devDependency
- added `test:lint:cycles` command to lint step
- added `.dpdmrc.yaml` config

**why it may break**:
- if repo has circular imports, lint will now fail
- this is intentional behavior, but may surface pre-upgrade issues

**how to verify**:
```sh
rhx git.repo.test --what lint
```

---

## hazard 4: jest config changes

**what changed**:
- added slowtest reporter
- added `.agent/.cache` exclusion
- reordered some config options

**why it may break**:
- slowtest reporter requires test-fns package (upgraded 1.7.2 → 1.15.8)
- if reporter fails to load, tests fail

**how to verify**:
```sh
rhx git.repo.test --what unit --mode apply
```

---

## hazard 5: CI workflow test shard overhaul

**what changed**:
- `test-integration` job replaced by `test-shards-integration` with matrix
- `test-acceptance-locally` job replaced by `test-shards-acceptance` with matrix
- new `enshard` job generates shard matrices
- union jobs aggregate shard results

**why it may break**:
- shard config files (`jest.integration.shards.jsonc`, `jest.acceptance.shards.jsonc`) don't exist
- action defaults to single shard if absent (backwards-compatible)

**how to verify**:
- push to branch, observe CI

---

## hazard 6: keyrack firewall step added to CI

**what changed**:
- `npx rhachet keyrack firewall` step added to integration and acceptance test jobs
- requires secrets to be configured in GitHub

**why it may break**:
- if repo has no secrets, firewall may fail

**how to verify**:
- push to branch, observe CI

---

## hazard 7: build step order change

**what changed**:
- build now runs before test:types in CI
- comment: "build before test:types, to ensure .dist/ artifacts are importable"

**why it may break**:
- if build fails, type check never runs

**how to verify**:
```sh
npm run build
```
