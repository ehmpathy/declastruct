## defect 1: unnecessary moduleNameMapper for .js extensions

**classification**: REPO CLEANUP

**why**: the upgrade added a moduleNameMapper for .js extensions to jest configs. however, this repo does not use .js extensions in imports — it uses extensionless imports throughout. the mapper was unnecessary and has been removed.

**evidence**:

```sh
# grep shows no .js relative imports in the codebase
npx rhachet run --skill grepsafe --pattern "from '\\./" --glob '*.ts'
# all imports are extensionless, e.g.:
# import { foo } from './bar';
# not: import { foo } from './bar.js';
```

**impact**: none — repo-specific cleanup only.

**feedback**: none needed. node16 module resolution does not require .js extensions if the codebase uses extensionless imports consistently.

---

## defect 2: circular dependency lint failure (transitive deps)

**classification**: REPO QUIRK

**why**: this repo's transitive deps (rhachet-artifact-git → as-procedure → simple-log-methods) pulled in old versions of domain-objects@0.31.9 and helpful-errors@1.5.3 which have circular dependencies.

**resolution**: upgraded rhachet-artifact-git from 1.1.5 to 1.1.6. the new version depends on as-procedure@1.1.13 which uses sdk-logs instead of simple-log-methods. this pulls fixed transitive deps (domain-objects@0.31.13, helpful-errors@1.7.3).

**note**: human rejected pnpm overrides. preference: fix at the source rather than patch transitive deps.

**evidence**:
```sh
# before: rhachet-artifact-git@1.1.5 → as-procedure@1.1.11 → simple-log-methods → domain-objects@0.31.9
# after: rhachet-artifact-git@1.1.6 → as-procedure@1.1.13 → sdk-logs → domain-objects@0.31.13
pnpm why domain-objects@0.31.13
```

**impact**: other repos should upgrade rhachet-artifact-git to 1.1.6+ to avoid this issue.

## defect 3: circular dependency lint failure (bottleneck)

**classification**: REPO QUIRK

**why**: bottleneck is a specific dependency of this repo. other repos may or may not use bottleneck.

**evidence**: bottleneck is not a common ehmpathy package — it's a rate limit library that this repo uses.

**impact**: other repos that use bottleneck will hit the same issue and should use the same exclusion pattern with documentation.

**feedback**: the exclusion pattern with documentation is the correct approach for third-party packages with internal cycles by design. no practice change needed — the exception clause already exists.

---

## defect 4: sdk-logs migration breaks CLI output assertions

**classification**: REPO QUIRK

**why**: migration from simple-log-methods to sdk-logs changed log behavior. `genLogMethods()` from sdk-logs outputs structured JSON, but CLI integration tests expected plain string output from `console.info`.

**resolution**: CLI files (apply.ts, plan.ts) now use plain `console.info` wrapped in LogMethods interface instead of `genLogMethods()`. this preserves human-readable output for CLI while it satisfies the LogMethods type.

**evidence**: 5 integration tests in apply.integration.test.ts failed because they spied on console.info and checked for substrings like 'yolo', 'CREATE', 'KEEP', 'DESTROY'. structured JSON output broke these assertions.

**impact**: repo-specific fix. other repos may need similar adjustments if they have CLI integration tests that assert on console output format.
